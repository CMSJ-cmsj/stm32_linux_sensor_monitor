# STM32‑Linux 串口传感器采集系统
> 基于 STM32F103C8T6 + X86‑Linux上位机双向串口通信项目
> 下位机：接收串口指令控制外设，采集传感器并按自定义协议上报数据
> 上位机：POSIX‑C原生实现，**不依赖libserial等第三方串口库**，实现帧解析、控制台交互、CSV日志持久化

## 项目简介
本项目分为 STM32 下位机与 Linux 上位机两部分，借助 CH340 USB‑TTL 模块实现双向串口通信。

**下位机能力：**
- 采集 MPU6050 六轴传感器（芯片内部硅片温度、三轴加速度、三轴陀螺仪）；ADC采集光照；
- 支持串口指令控制 LED、蜂鸣器、SG90舵机；
- 可配置温度报警上下阈值，实现声光报警；
- 按照自定义通信协议，应答指令、上报传感器原始数据。

**上位机能力：**
- 单线程 `poll()` IO多路复用，同时监听串口设备与标准输入键盘；
- 环形字节缓冲区作为底层蓄水池；三段式有限状态机解析自定义传感器上报帧；
- 控制台透传下发原始串口指令给STM32；
- 解析传感器键‑值(KV)数据，写入CSV日志，调用`fsync()`强制刷盘，降低断电丢失日志风险。

⚠️两套方向完全独立的通信协议，不可混用
 - 📥 **Linux → STM32 下发控制帧：** `@载荷#!`
 - 📤 **STM32 → Linux 上报传感器帧：** `$T:xx.x L:xxx AX:xx AY:xx AZ:xx GX:xx GY:xx GZ:xx#\r\n`

## 通信协议详情

### 1. 上位机 → STM32（下发控制指令）
报文格式：`@载荷#!`
- `@` 帧头；`#!` 为固定双字符帧尾；中间部分为业务载荷；
- Linux上位机**只做字节透传，不解析指令语义**；全部指令解析逻辑运行在STM32下位机。

示例指令：

@LED:ON#!        // 打开 LED
@LED:OFF#!       // 关闭 LED
@BEEP:ON#!       // 开启蜂鸣器
@SG90:90#!       // 舵机设置 90°
@GET_DATA#!      // 请求读取传感器数据
@SET_H:30.5#!    // 设置报警高温阈值
@SET_L:22.0#!    // 设置报警低温阈值
@ALARM:ON#!      // 开启声光报警
@ALARM:OFF#!     // 关闭声光报警

### 2. STM32 → Linux（应答/传感器上报帧）
报文格式：`$T:温度 L:光照 AX:x AY:y AZ:z GX:x GY:y GZ:z#\r\n`
`$` 帧头；`#` 帧结束标记；`\r\n`仅用于串口助手换行显示，上位机解析器直接丢弃。
    示例传感器上报报文：
    $T:25.1 L:1024 AX:120 AY:211 AZ:1630 GX:-11 GY:22 GZ:-33#

    应答报文示例（同样以`$`开头，`#`结尾）：
    $Resp:LED ON OK#


## Linux上位机编译、运行说明

### 编译
进入上位机源码目录执行make
编译产物：可执行文件 `uart_host`

### 清理编译中间文件
make clean

### 程序运行
串口设备一般为 `/dev/ttyUSB0`，根据实际环境修改设备路径

# 授予串口访问权限
sudo chmod 666 /dev/ttyUSB0

# 启动上位机程序
./uart_host /dev/ttyUSB0

在控制台直接输入完整指令，按下回车即可下发给 STM32；
`Ctrl + C` 安全退出程序，自动关闭串口、关闭 CSV 文件，释放全部资源；
传感器数据自动输出保存到当前目录 `sensor_log.csv`。
    Makefile 编译参数说明
    `-Wall -Wextra`：开启全部编译警告；
    `-std=c11`：使用 C11 语言标准；
    `-g`：生成 gdb 调试符号；
    `-D_POSIX_C_SOURCE=200809L`：启用 POSIX.2008 接口（`gettimeofday`、`strtok_r`等）；
    IO 全部使用 POSIX 原生系统调用 `open/read/write/fsync/close`，不使用 C 库`FILE*`文件接口。

## Linux 上位机模块说明

| 模块 | 功能简述 |
| --- | --- |
| `uart_port` | termios 串口配置，设置原始二进制模式；封装串口 open、close、write 系统调用 |
| `ring_buf` | 256 字节环形 FIFO，串口原始字节蓄水池；缓冲区溢出一次性告警；仅缓存字节，不处理帧协议 |
| `sensor_frame_parser` | 三段状态机解析`$...#`上报帧；内部`frame_busy`忙标记做流控；输出独立帧载荷副本；防护恶意无限半帧；**契约：收到完整帧后必须调用`sensor_parser_release()`** |
| `console_cmd` | 读取标准输入 stdin，按行读取用户输入，剥离`\r`、`\n`换行符，原始字节透传给串口下发 |
| `csv_log` | CSV 日志模块；空文件自动写入表头；每条数据写完执行`fsync()`强制刷盘；IO 故障必须先调用 release 解析器，再释放资源退出 |
| `main.c` | poll 多路 IO 监听串口与键盘；SIGINT 信号安全退出；消费环形缓冲区，单字节喂入解析器；`strtok_r+strchr`完成 KV 键‑值解析；控制台打印数据、写入 CSV、统一资源回收 |

### ⚠️核心代码契约（红线）

当 `sensor_parser_input_byte()` 返回值等于`1`，代表解析得到一帧完整上报帧。
**无论业务正常、KV 解析失败、CSV 磁盘 IO 报错，所有代码执行路径，都必须调用一次`sensor_parser_release()`**。
如果漏调用，`frame_busy`将永久置为 true，解析器会直接丢弃后续所有串口字节，接收功能完全锁死；即使进程即将退出，代码路径也要遵守该契约。

### 三层防护架构

| 防护层级 | 模块 | 解决风险 | 实现手段 |
| --- | --- | --- | --- |
| 协议解析层 | sensor_frame_parser | 恶意无限半帧；未处理完的帧被新数据覆盖 | 128 字节组帧缓冲区溢出告警丢弃；`frame_busy`忙标记；输出独立帧副本；处理完成必须 release |
| 业务调度层 | main poll + ring_buf | 避免解析器被硬件异步抢占 | 串口原始字节先存入 ring_buf；主循环轮询消费缓冲区，单字节送入解析器 |
| 底层字节兜底层 | ring_buf | 瞬时流量超过上层处理速度 | ring_buf 写满后丢弃新来字节，打印一次性严重告警 |

### 完整数据流

1. **下发链路（主机 → STM32）**
键盘 stdin 输入 → `console_read_line()`读取一行 → `uart_write_buf()`写入串口 → CH340 硬件 → STM32 USART1 中断接收 → 下位机状态机解析 → 执行业务外设动作，组装应答帧向上返回。
2. **上报链路（STM32 → 主机）**
STM32 组装传感器帧输出串口 → Linux `read()`读取字节写入 ring_buf；主循环消费 ring_buf，逐个字节送入解析器；识别完整帧后做 KV 解析；控制台打印解析结果；`gettimeofday()`获取 Unix 时间戳写入 CSV 并执行 fsync；调用`sensor_parser_release()`释放忙标记，等待下一帧。

## STM32 下位机说明

### 架构要点

1. USART1 中断只负责字节接收与状态机流转；**所有指令解析业务逻辑放置主循环 while (1)，不在中断内执行业务**；
2. TIM2 周期中断只置标志位，传感器读取、OLED 刷新、报警逻辑全部放在主循环；
3. 软件 I2C 驱动 OLED 与 MPU6050；ADC 实现光照采样，滑动平均滤波抑制噪声。

### 历史关键 Bug 复盘

现象：下发合法指令，外设可以正常动作，但串口打印载荷概率性乱码，`sscanf`偶尔解析得到随机数值。

1. **根因**：USART 中断函数内部使用`static`局部变量保存状态机`RxState`、`pRxPacket`。编译器不知道硬件中断会异步抢占执行，将变量缓存至 CPU 寄存器；寄存器副本和真实 SRAM 内存不一致，产生野数组下标，字符串`\0`终止符错位。`strncmp`前缀匹配正常，但`printf("%s")`读取脏内存出现乱码。
2. **修复方案**：将状态变量迁移至全局作用域，添加`volatile`修饰，强制每次读写访问真实 SRAM，**状态机跳转业务逻辑完全不改动**。
3. 经验教训：调试快照、dump 打印等脚手架代码，本身会引入竞态、栈溢出等次生病；调试代码归档文档，**不要留在交付业务代码中**；优先使用 OLED 硬件观测，不完全依赖串口 printf。

### 业务加固点

- 帧下标越界防护，载荷超限直接丢弃帧，复位状态机；
- `Serial_Printf`使用`vsnprintf`代替无边界`vsprintf`，增加缓冲区截断保护，防止栈溢出；
- 协议校验：检测`#`后面不是`!`，丢弃非法帧并输出业务告警；
- 交付版本移除全部调试 dbg 变量、快照缓冲区、OLED 调试面板；调试信息归档至`log_record/DebugRecord.md`。

### 现存待优化点

- 当前下位机串口使用单帧全局缓冲区，高速连续下发报文会发生帧覆盖，可以升级接收环形 FIFO；
- 缺少半帧软件超时复位；串口断线可能状态机卡死；
- Keil‑MDK MicroLib 下`sscanf`浮点`%f`存在兼容性风险，可以手写字符串解析替代库函数；
- 尽量不要在指令解析回调函数内部执行大量格式化串口打印。

## 退出机制说明

上位机捕获`SIGINT(Ctrl+C)`信号，设置程序退出标记；主循环安全收尾，依次关闭串口 fd、CSV 文件 fd，释放全部资源，不会发生资源泄漏。

## 注意事项

1. 串口波特率 9600‑8N1 上下位机必须保持一致；
2. CH340 与 STM32 之间必须共地，TX/RX 交叉接线；
3. CSV 日志每次写入调用`fsync()`，降低断电丢失日志，但会带来少量性能开销；
4. STM32 中断内部禁止执行阻塞 I2C、大量格式化打印等耗时操作；
5. 修改下位机业务代码后，请执行`TestCases.md`回归测试，防止协议功能回归。
